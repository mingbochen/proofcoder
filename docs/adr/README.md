# 架构决策记录（ADR）

ADR 记录某条约束为什么这样定、为什么改变，以及放弃了哪些方案。[开发规范](../DEVELOPMENT_SPEC.md)说明必须成立什么，ADR 说明为什么。

## 何时需要写

- 改变开发规范第 3 节的范围或非目标。
- 放宽或收紧工具、命令、路径、凭据等安全约束。
- 选择会长期影响架构的方案，例如检查点的存储方式、模型提供方抽象的边界。
- 修订开发规范第 2 节红线。这需要单独的 ADR，并由用户明确批准。

bug 修复、纯实现细节和不改变约束的重构不需要 ADR。

## 规则

- 文件名为 `NNNN-短横线标题.md`。编号递增，不复用。
- 从 [`0000-template.md`](0000-template.md) 复制后填写。
- 状态从“提议”开始，之后变为“已接受”或“已拒绝”；被新决策取代时改为“已被 ADR-NNNN 取代”。
- 已接受的 ADR 不修改正文。决策改变时写一篇新的 ADR，并只修改旧 ADR 的状态行。
- ADR 要求的规范变更，必须和 ADR 在同一个变更中提交。
- ADR 的状态以合并进 `main` 的版本为准。
