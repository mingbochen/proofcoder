# ADR-0002：提供本地浏览器界面

- 状态：已接受
- 日期：2026-09-12 作出决策并实现；2026-09-13 合并，并补记本 ADR
- 决策者：chenmingboi（仓库作者）
- 相关：开发规范 §3、§4.6、§5.1；PR #1；`docs/DESIGN.md`；`docs/THREAT_MODEL.md` 的 TM-24、TM-25

## 背景

- 运行 ProofCoder 需要记住多个命令行参数，对不熟悉命令行的用户门槛较高。
- 开发规范 v2.1 §3.2 把“图形界面和复杂 TUI”列为非目标，同时说明非目标不是永久禁止。
- 开发规范 §2.4 要求运行依赖保持最小化，新增运行依赖必须说明不可替代性。
- 浏览器界面会把本地文件与命令权限暴露给一个 HTTP 接口。

## 决策

我们新增 `proofcoder serve`，作为现有 AgentLoop 的展示层：

- 使用标准库 HTTP 服务器和一个无需构建的静态页面，不新增运行依赖，不加载任何外部资源。
- 运行与 `proofcoder run` 相同的 AgentLoop。页面只渲染轨迹同样收到的脱敏事件，不引入第二套完成判定。
- 为 AgentLoop 增加协作式取消回调，在步骤之间和工具调用之间检查；终止原因沿用已有的 `interrupted`。
- 访问控制：默认只监听回环地址；每个进程生成会话令牌，只写入本服务返回的页面；校验 `Host` 与 `Origin`；限制请求体大小；使用严格的内容安全策略。
- 从开发规范的非目标中移除“图形界面”；复杂 TUI 仍然是非目标。

## 备选方案

- **只保留命令行。** 不增加攻击面，但使用门槛不变。未选。
- **引入 Web 框架（如 FastAPI、Flask）和前端构建链。** 开发更方便，但违反 §2.4 的依赖最小化，扩大供应链面；标准库足以支撑单用户的本地服务。未选。
- **复杂 TUI。** 不开放 HTTP 接口，但交互能力受限，而且仍在非目标中。未选。
- **用 EventSource 推送事件。** 实现简单，但 EventSource 不能设置请求头，令牌只能放进 URL，会进入浏览器历史和日志。改用可以携带请求头的长轮询。未选。

## 后果

- **正面：** 不需要记忆命令，就能运行、观察、停止和回放任务。
- **负面与新增风险：**
  - 新增本地 HTTP 攻击面（TM-24）。上述措施是访问控制，不是沙箱。
  - 页面把同一工作区的多个任务显示在一条线程里，但在阶段 I 之前每次运行相互独立，模型看不到之前的任务。
  - 默认端口 8765 可能落入 Windows 的保留端口段，此时需要用 `--port` 指定其他端口。
  - 取消是协作式的，进行中的模型请求或命令要先执行完，运行才会停止。
- **需要同步修改：** 开发规范 §3、§4.6、§5.1；README；DESIGN；THREAT_MODEL。
